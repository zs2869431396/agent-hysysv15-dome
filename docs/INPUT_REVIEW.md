# 双阶段输入审核

2026 年 10 月 4 日，输入流程调整为：抽取 → 审核 → 确定性选型与编译 → 追问或执行。
CLI、单遍流程和 Streamlit 使用同一套审核逻辑。默认使用页面或环境变量配置的同一模型
进行两次独立调用，无须填写第二个密钥或更换接口。

## 审核职责

审核提示词在 `reactor_agent/review.py` 的 `REVIEW_PROMPT` 中，以中文编写。
输入包括题目原文和第一阶段的结构化事实。输出包含字段修正、逐字原文依据和待确认问题。
审核不能执行 HYSYS、指定工具参数或生成模拟结果。反应器选择仍由 `selection.py` 决定。

每个修正的字段必须属于抽取契约，引用必须存在于原文，修正值必须通过嵌套类型校验；
修改的主要数值还会对照引用检查量纲与数值。最终结果仍经过原有 grounding、归一化、
元素配平和工具预检。字段修正缺少原文依据、数值依据不符或值格式无效时，拒绝该修正、
保留原抽取值；关联的单位或组成基准也一并回退，避免错配。再检查原文能否通过确定性
规则证明该字段：纯进料的组成、单工况已有压力、绝热出口温度属于计算结果，以及原文
配平方程与等摩尔比例允许的异构体总系数恢复。这些已被证明的条件不再追问，其他未解决
的修正转为可回答的阻塞追问。模型的 `missing_information` 是备注，真正缺少的必需输入
由原有预检检查，不要求用户确认这份内部列表。审核回复整体结构无效、字段未知、调用
失败或预算耗尽时仍报告运行失败。未解决的歧义不会进入 HYSYS 执行。
审核回复的嵌套结构不合法时，报告具体字段路径（例如 `$.questions[0].reason` 缺失），
并在总请求预算允许时进行一次格式修复。修复后仍需经过全部原文依据和确定性检查，
不会跳过审核。`format_attempts` 保存已解析的审核回复及格式错误，配置密钥会被遮蔽；
修复失败时也保留这些记录，可从页面详情、`process.json` 和 `state.json` 查看。
这些检查不能完全证明模型对所有语义的理解正确，工作站测试仍是必要的。

审核提出的问题通过原有检查点暂停。无效答案继续阻塞，有效答案合并后重新规划；
不会重新调用抽取或审核模型。审核记录在图状态的 `review` 中，最终 `state.json`
包含 `input_review`，页面的 `process.json` 记录审核阶段及其详情。单遍流程的摘要也包含审核记录。
确定性证明记录在 `deterministic_resolutions`，被拒绝的修正仍保留在 `rejected_corrections`。
审核返回值通过类型校验、且与原值相同时，不属于事实修改，不因引用格式生成追问，
并记入 `unchanged_corrections`；原值仍经过原有 grounding 和全部预检。原抽取组分若与
原文反应式的全部物质一致，可以消除无依据组分修改带来的追问；缺项、未知组分或额外
组分不能使用这项证明。煤的建模定义不因此获得确认，仍由独立追问处理。
HYSYS 可提供的比热和反应热、非动力学计算不需要的设备尺寸，不作为“用户未提供”备注。

## 多工况压力

对于每个工况都明确给出进料和出口压力、且说明无压降的题目，系统将各工况压力分别
传入其进料规格。例如同为 750°C 的 5 bar 和 20 bar 工况，会得到两份进料压力分别
为 5 bar、20 bar、压降为零的规格，不会要求用户选择一个公共进料压力。

相同温度的多个工况保留重复温度和对应压力，案例文件名加上工况编号，防止覆盖。
如果各工况只有出口压力而没有进料压力或压降依据，仍会追问；温度和压力数量不能对应
时也会阻塞，不自行猜测对应关系。

## 配置与验证

默认 `TR_REVIEW=1`；`TR_REVIEW=0` 可用于与旧单阶段流程对照。
正常路径为两个模型请求。`TR_ATTEMPTS` 控制 HTTP 重试，不代表整个任务只调用一次模型。
格式修复会增加一次模型调用，该调用自身的 HTTP 回退和重试也受同一总请求预算约束。
`TR_MAX_REQUESTS` 仍约束同一个客户端的总请求数；设为 1 时默认流程无法完成审核。
网页设置现在也读取这些环境配置。无需安装新的依赖。

`reactor_agent/test_review.py` 用离线传输模拟真实的两次请求，覆盖遗漏修正、缺失追问、
无效答案、无依据数值拒绝、预算耗尽、两个压力工况、案例名不重叠、单遍流程和页面事件。
`fixtures/toluene_review_failure.json` 保存用户提供的真实审核修正（首次抽取相关字段按
用户展示的内容重建），覆盖长篇推理冒充引用、异构体被合并、绝热出口温度被误填和多余追问。
`fixtures/gasification_review_input.json` 保存工作站提供的真实首次抽取与题目。
该次失败的审核原始回复未保存，因此格式修复测试使用明确构造的错误审核回复，
验证修复、失败诊断、请求预算和确认煤及体积基准后继续规划的流程。
`fixtures/gasification_review_noop.json` 保存用户随后提供的真实审核回复，用于验证
相同组分被当成修正并使用省略号引用时，不会多问一个 `species` 问题。
旧单阶段测试夹具明确关闭审核，继续检查原有流程；新测试独立验证默认双阶段路径。
本地验证不调用付费模型，也不连接 HYSYS。实际模型效果和新增压力工况需要在工作站复核。
