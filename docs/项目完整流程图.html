用户提交自然语言

用户 · Streamlit 或 CLI

描述进料、反应、温压和想比较的工况；选择“生成模拟方案”或“执行 HYSYS 模拟”。

输入：一句或多句工艺需求
输出：原始文本、执行模式和初始图状态

02

intake：首次 LLM 抽取

LLM 提取 · 程序做格式与原文校验

模型把原文整理为 facts：组分、进料组成、流量、温压、反应、转化率和工况。程序检查字段结构，并把数值找不到原文依据的字段名记进 ungrounded。

输入：用户原话
输出：facts、ungrounded、抽取错误
代码：intake.py L20–34 · extraction.py L592–663、L956–995
↓
03

review：程序先查漏，再按需让 LLM 回原文核对

程序主导 · 第二次 LLM 调用有条件

程序先补回原文明示且可唯一确定的单位或组成基准，再调用同一套规划规则试规划、预检，从阻塞问题得到 target_fields。此时没有启动 HYSYS。若审核配置被关闭，整个 review 补漏环节会跳过。

输入：原文、facts、初始状态
输出：可补漏的目标字段、预检记录
代码：input_recovery.py L19–111、L114–125 · review.py L122–137
↓
是否有可补漏的目标字段？

没有 → 跳过第二次 LLM

直接保留程序已核对的信息。需要用户确认的建模歧义，不让模型猜。

有 → 定向调用 LLM

只核对 target_fields，逐字引用原文；程序检查范围、格式、证据、数值和单位，再次预检。不合格修正回退。

两条路径汇合 → 用更新后的事实重新计算 ungrounded；补漏调用失败则保留原事实。
↓
04

plan：正式形成模拟方案

程序规则 · 最终放行条件在这里形成

先合并用户已经回答的问题，再把事实归一化为 ProcessRequest，按规则选反应器、查工具能力，形成含假设与工况的 ModelingPlan。无阻塞时逐工况编译 spec JSON，并做离线规格预检。

归一化反应器选型能力检查编译 + 预检
输入：已核对的 facts、用户回答
输出：blocking、decision、cases[].spec、status
代码：plan.py L82–177 · compiler.py L411–452 · selection.py L363–547
↓
plan 的结果决定图往哪里走

有阻塞问题 → ask

LangGraph interrupt 暂停，向用户询问真实缺口；回答后用同一 thread_id 从检查点恢复，回到 plan 重新规划。

不支持 / 校验失败 → explain

不给工具下发可执行规格；报告说明选型、缺口或错误原因，不声称完成模拟。

READY → execute 节点

规格已通过预检。是否真正启动 HYSYS，还要看用户是否选择“执行模式”。

↶ ask 的回答返回 plan，不会重新从 intake 抽取整段原文；追问轮次有上限。
代码：ask.py L33–88 · graph.py L78–91、L94–99
READY 后：方案模式与执行模式

只生成方案

execute 节点是空操作；保存规格和说明，状态保持 READY。没有 HYSYS 出口数值，也没有新建 .hsc。

execute.py L35–37 · report.py L218–220

执行 HYSYS

逐工况调用适配器；同规格已有成功结果时跳过重复执行。出现连接失败或超时，停止后续工况。

execute.py L46–77
↓
05

适配器：写 spec.json，启动独立工具进程

程序规则 · 一工况一目录

适配器创建唯一尝试目录，写入已编译的 spec.json，执行 python -m hysys_tools --spec … --folder …。工作站锁让 COM 操作串行；调用设置超时并保存 stdout/stderr。

传给工具：规格文件路径、输出目录；文件内容含物性、进料、反应、反应器和假设
并未传入：模型生成的 shell 命令；模型不能控制命令参数
代码：hysys_cli.py L300–386
↓
06

hysys_tools：再次预检 → COM 建模 → 求解读回

工具层 · HYSYS 负责数值计算

子进程读取并校验规格；通过后用 GetActiveObject('HYSYS.Application') 连接正在运行的 HYSYS。创建新案例，配置物性/反应/物流/反应器，求解并读取出口，再做独立校验，保存 .hsc、result.json 和 steps.json。

输入：单工况 spec.json
输出：案例文件、出口数据、热负荷、校验与操作步骤
代码：main.py L555–626、L119–125、L170–175、L204–251 · reactor.py L676、L893
↓
07

适配器验收结果

程序规则 · 结果文件是主要返回通道

读取 result.json，核对工具状态、子进程退出码以及案例/出口/校验等证据，记录运行台账。每个工况最终得到 PASS、PARTIAL 或 FAILED 等状态。

代码：hysys_cli.py L349–374、L401–409 · execute.py L56–88
↓
08

explain：生成中文说明和运行文件

程序模板 · 不重新让 LLM 猜数值

从图状态组织选型理由、待确认问题、假设和执行结果。方案模式明确写“尚未运行模拟”；执行模式用 HYSYS 读回值生成出口说明、工况对比和过程记录。保存 state.json、explanation.txt 以及已编译的各工况规格。

方案模式：建模说明 + 规格，无模拟数值
执行模式：HYSYS 结果 + 校验 + 案例文件
代码：explain.py L30–32 · report.py L132–228 · graph.py L102–119

五份关键数据

  • facts：用户原话里提取到了什么。
  • review：查漏、补漏和拒绝理由。
  • ModelingPlan：选型、能力、工况、假设与问题。
  • spec.json：让工具怎么建模。
  • result.json：HYSYS 实际算出什么。

读图时记住

“review 试规划”调用与正式 plan 相同的规则来找缺口，但最终追问、放行和每工况规格仍由正式 plan 决定。方案模式在图中也经过 execute 节点，只是该节点不启动工具。
