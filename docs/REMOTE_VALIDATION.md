# 工具层修复版：远程测试说明

版本：`2026-10-02-reliability-1`。本地测试不调用 HYSYS；新版是否在工作站正常运行，以这次远程回传为准。

## 你需要做什么

1. 将修复版 ZIP 复制到远程电脑，**解压到一个新文件夹**，保留旧文件夹和历史结果作为对照。
2. 打开 HYSYS，处理已有弹窗。测试仅使用自己新建的案例。
3. 双击 **`Run-Remote-Validation.cmd`**。已有 `Run-Tool-Layer.cmd` 也会进入同一验证流程。
4. 等待脚本结束。通常需要几分钟；单个模拟最多等待 180 秒，健康检查最多 30 秒。超时只停止本次 Python 工作进程，保留 HYSYS，并停止后续模拟。
5. 将窗口最后显示的 **`tool-layer-runs/acceptance-日期时间-随机编号.zip` 整个复制回来**。成功或失败都回传 ZIP，无需只截最后一行。

前提沿用已验证环境：Windows、Python 3.12、pywin32、HYSYS V15。此次没有新增第三方依赖。若提示找不到 Python，在该目录终端执行 `python --version`，确认使用原来能运行工具层的解释器。不要同时运行其他工具脚本或操作本次新建案例。

## 脚本运行内容

1. 运行原有离线自检和新增可靠性回归测试，保存 stdout/stderr。
2. 生成四份示例 spec 和各自预检报告。
3. 检查 HYSYS 连接并保存环境信息。
4. 串行执行甲苯、重整 710°C、重整 600°C，每个工况使用全新目录。
5. 检查稳定读数证据、保存的 HSC，并将转化率、组分流量、热负荷与历史基线进行容差比较。
6. 对原题气化输入验证“应被预检拒绝且不创建 HSC”。**这是输入保护测试，不是气化模拟通过。**
7. 再检查 HYSYS 连接，生成汇总与压缩包。

任一正向工况失败、超时或无法确认案例关闭，脚本停止后续模拟，保留当前证据。把该次 ZIP 回传后再定位。

## 怎样判断结果

- `BASELINE_PASS_GASIFICATION_STILL_BLOCKED`：新版已通过甲苯和重整三个工况的自动验收，气化仍缺建模信息。
- `FAILED`：看 `summary.json` 的 `error`，以及对应目录的 `result.json`、`stdout.txt`、`stderr.txt`。
- `OFFLINE_PASS_REMOTE_NOT_RUN`：只做了离线检查，不能证明新版已通过 HYSYS。

真机验收时还应打开成功的 `.hsc`，核对反应器类型、反应集、进出口条件和组成。自动回读与守恒检查不能独立证明热力学模型完全适用。

## 这次修复了什么

- 未达到连续稳定读数要求时明确失败，不再以最后一次有效读数继续返回成功。
- 稳定性检查涵盖分相流量、组成、温度、压力、质量流量和热负荷，检查读取前后的求解器状态。
- 拒绝 NaN/Infinity、HYSYS 未知值、组分数组长度不匹配；核对出口压力、指定出口温度和绝热热负荷。
- 已运行但结果不符合目标时归为结果问题，避免 Agent 错改输入。
- 预检检查文件名、无效字段、冲突转化率、重复组分别名、不可能的压降。
- 多个 Conversion 反应暂时拒绝：当前独立校验不能正确区分其各自转化率，不能把总转化率冒充各反应转化率。
- 新增 `blocking_questions`，与普通 `open_questions` 区分；气化关键问题未解决时拒绝执行。
- 空白案例检查提前；已有物流或设备的案例不进入 basis 编辑，也不保存或关闭。
- 已有同名 HSC 不覆盖；结果 JSON 原子写入，写盘失败不能静默当成功。
- 缺少 pywin32 或连接失败时提供结构化错误；能力表区分历史验证、实验能力和不支持组合。
- 验证脚本提供超时、同用户多副本互斥、自动汇总、历史基线比较与证据 ZIP。

## 尚未解决的事项

1. **Equilibrium**：仍明确禁用，需工作站帮助和接口验证。
2. **气化定量结果**：需明确 80000 Nm³/h 所指流股、标准状态、煤的定义，并验证固体碳及残碳的实际读回；不会自行改成 kg/h。
3. **物理模型适用性**：重整 Gibbs 数据适用温区、气化固体支持仍需真实证据。
4. **CSTR/PFR**：当前没有执行实现。
5. **并发**：新验证脚本之间有互斥；直接调用 `python -m hysys_tools` 的其他程序仍需自行串行调度。

本轮聚焦工具层；`../hysys-ai` 中的旧选型草稿不在本次部署包内，后续搭建 Agent 时按实施规划重做其不一致分支。

## 不连接 HYSYS 的检查

双击 `Run-Offline-Checks.cmd`，或在项目目录执行：

```powershell
python -m hysys_tools.remote_check --offline
```

这也会生成 ZIP，但状态明确标识为离线。CLI 仍支持：

```powershell
python -m hysys_tools --list-capabilities
python -m hysys_tools --validate-only --spec path\to\spec.json
```
