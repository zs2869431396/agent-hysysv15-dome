# AI 驱动的化工反应器智能建模项目报告

日期：2026 年 10 月 4 日

## 项目目标与实现情况

本项目针对考核中的甲苯歧化、甲烷蒸汽重整和水煤浆气化，完成了自然语言输入、反应器选型、HYSYS 建模和结果返回的闭环。三个场景已有工作站真实运行结果。我希望用户既能得到计算数值，也能看懂选型理由、建模假设和校验依据，因此在中文聊天页面中加入了实际运行过程展示。

## 技术选型与系统架构

我使用 Python 3.12 开发，通过 pywin32 调用 Aspen HYSYS V15 的 COM 接口，直接创建物流、配置反应器、读取结果并保存案例。这条路径便于重复运行和读回验证，减少了对窗口位置及鼠标操作的依赖。前端采用 Streamlit，复用 Python 业务逻辑；流程采用 LangGraph 和检查点机制，支持追问后继续同一个任务。

系统分为智能体层与工具层。模型从原文抽取组分、组成、流量、温压和反应信息；程序负责单位归一化、选型、规格编译及预检；工具层驱动 HYSYS 求解并检查结果。输入有缺口时，第二次模型调用只针对缺失字段查原文，候选补充必须通过校验。真实缺失或存在歧义的条件由程序追问，确认前不执行 HYSYS。最终数值来自工具结果，报告由程序组织。

页面支持方案模式和执行模式，前者返回通过预检的规格，后者才调用 HYSYS。模型服务地址和名称可在页面配置，当前实测模型为 qwen3.7-flash，采用兼容 /chat/completions 的接口。抽取提示词中的 JSON 示例使用乙醇脱水，与三个考核场景不同；下游规则仍有明确的领域覆盖范围。

## 三个场景的选型与结果

| 场景 | 选型与建模条件 | 工作站返回结果 |
| --- | --- | --- |
| 甲苯歧化 | 无动力学参数，已知转化率 50%，采用 Conversion；进料 10000 kg/h、380°C、2.5 MPa | 绝热出口 378.28°C；摩尔组成为甲苯 50%、苯 25%、邻间对二甲苯各约 8.33%；转化率达到 50% |
| 甲烷蒸汽重整 | 两个可逆反应构成闭合网络，采用 Equilibrium；甲烷与水摩尔比 1:2.7，入口 520°C，压力 13.5 bar | 710°C 与 600°C 下，甲烷转化率为 54.16% 和 30.50%；外部供热约 40.06 MW 和 20.24 MW；两反应 Q/K 接近 1 |
| 水煤浆气化 | 1400°C 高温下考虑多种候选产物，采用 Gibbs 与饱和碳组合路线；压力 40 bar、煤质量分数 62% | CO 收率 40.14%，碳转化率 41.16%；湿基气相 CO 摩尔分数约 50.01%；外部供热约 84.66 MW，出口保留残余固体碳 |

甲苯原题未给三种异构体比例和热边界，我采用等摩尔分配及绝热假设并写入报告。重整原题允许自定流量，我取甲烷 1000 kmol/h，总进料 3700 kmol/h，按 8000 h/a 折算甲烷约 12.83 万吨/年。

气化先由用户确认 80000 Nm³/h 指混合总进料的标准体积当量、基准为 0°C / 101.325 kPa，以及煤按纯碳处理，再换算建模。CO 收率按净生成 CO 的摩尔量除以进料碳原子摩尔量计算，与碳转化率和出口 CO 摩尔分数分别报告。

## 探索过程与问题处理

实现过程中，我先打通工具调用，再接入自然语言和界面，并用变更条件的案例检查链路是否跟随输入。工作站还运行了 10 bar、650°C 与 750°C 的重整对比：甲烷转化率为 47.78% 和 73.99%，氢气流量约 1776.78 和 2583.07 kmol/h，供热约 34.09 和 55.98 MW。该次任务经过总流量确认后完成计算，结果呈现了升温促进重整的趋势。

最初，重整回复中的 conversion_basis 为 null，却被严格字符串类型拒绝，触发了无效重试。我把允许缺失的文本字段改为可空类型，同时保留数组和对象的严格校验，并加入真实回复回归测试。这个问题说明，校验器也可能把正确输入挡住，不能把所有失败都归因于模型。

甲苯测试中，模型把三种二甲苯各写成系数 1，导致反应不守恒。修复时根据原文中配平的总反应和等分条件恢复各 1/3，并保留元素预检。气化则曾在计算成功后因报告层类型处理不当而报错；我修正结果兼容处理，并从已保存产物恢复报告，避免重复模拟。

另一项调整是取消逐字段的全面模型审核。实际测试中，审核模型会清空已给出的流量，或把工程判断变成多余问题。现在先由程序预检，有数据缺口才定向补漏；候选修正不能清空已有事实、缩减已有组分，模型提出的问题也不直接成为阻塞项。最新工作站页面已按预期只保留气化的体积基准与纯碳假设两项确认。

## 验证与能力边界

最新重构后的离线验证记录为智能体 496 项、打包器 17 项测试通过；工具层已有 122 项自检、184 项回归及真机验收记录。页面按实际事件展示输入、抽取、预检、追问、各工况执行和报告生成，保存规格、状态及过程文件，便于复核。上述三个场景的定量结果来自已有真机运行；最新补漏分支尚不能视为完成全部在线模型与真机复验。

当前能力集中于已验收的 Conversion、等温气相 Equilibrium、等温 Gibbs 及饱和碳路线，CSTR 和 PFR 未实现。重整 Q/K 接近 1 证明与所用平衡常数自洽，不能证明高温热力学数据本身准确。气化没有氧气进料，热负荷应解释为外部供热；煤按纯碳也是需确认的简化。额外场景仍要经过能力检查。

## AI 协作与交付

我使用 AI 编程助手讨论方案、实现代码、定位故障和补充回归测试，再通过工作站运行及产物复核判断修改是否有效。开发中保留失败记录，把暴露的问题转为测试，并根据实际反馈调整架构。代码和 README 已上传 GitHub；本报告按考核要求整理。完整提交还需配套三个场景从输入到返回结果的录屏、脱敏后的 AI 开发记录，并准备现场 Live Demo。
